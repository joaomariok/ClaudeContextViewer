# context-viewer

A Claude Code mod (function-hooks plugin) that draws the context window above the prompt. `README.md` covers what it shows and its settings.

## Verify

```
claude plugin validate .
claude plugin test .
npx -y -p typescript@5.6.3 tsc -p .
```

All three pass before work counts as done (plus `cd extension && npm test` when `hooks/format.ts` or `extension/` changes). `tsconfig.json` and `.claude-plugin/types/` are generated by the engine on each load (gitignored); the API reference is `.claude-plugin/types/claude-code/index.d.ts`, so grep it for an event or prop before using one.

## Surfaces

The band draws in the terminal and the desktop app only. The VS Code extension (2.1.294) draws no mod UI at all (anthropics/claude-code#99045), so keep the mod's drawing to `terminal` and `desktop`; VS Code gets its figures through the snapshot file and `extension/` (below).

## Gotchas

- **State outlives a reload.** `$.state` keeps the value an older version of the module wrote, so every read tolerates an older `View` shape (see `usageParts`, `v.limits ?? []`).
- **Mirror `/context`, not the true trigger.** `autoCompactThreshold` is the engine's `/context` figure and ignores `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`; the owner chose to keep it as is.
- **Colours are the mod's own palette**, since `/context`'s theme colours repeat a grey across categories.
- **`next` is reserved**: a local named `next` inside a hook fails the module load.
- **`userConfig` fields are strict**: only `type`, `title`, `description`, `default`, `options`, `min`/`max`, `required`, `multiple`, `sensitive`. Keys are snake_case.

## VS Code extension (`extension/`)

- The mod writes a `Snapshot` (`hooks/format.ts`) to `~/.claude/context-viewer/<sessionId>.json` on each `session.measure`, and on each typed prompt (`turn.start`, stamping `promptedAt` so the extension can follow the session in use); the extension reads it. Change the shape in `format.ts` and both sides follow; bump `version` on a breaking change.
- `hooks/format.ts` is the shared code: plain TypeScript, no `claude-code` runtime import, no JSX, so the extension's `tsc` (CommonJS, `rootDir: ".."`) compiles it too.
- Extension tests are `*.spec.ts` (node:test), never `*.test.ts`: `claude plugin test` runs every `*.test.ts` under the repo and has no ignore option.
- Everything else about the extension is in `extension/CLAUDE.md`.

## Tests (`claude-code/testing`)

- Hooks registered on the test's `on` stand in for the engine beneath the plugin; `engine()` in `hooks/register.test.ts` is the shared stand-in. One test hook per event.
- An op event answers `{ value }` (e.g. `session.usage`); `session.measure` answers `{ changed }`.
- `find({ text: 'string' })` matches by inclusion; use `whole()` for an exact line.
- A test cannot seed `$.state`; test state-shape handling through an exported pure function.
- Per-setting tests pass values with `test(name, { options }, body)`.
